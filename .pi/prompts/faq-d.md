你正在执行 FAQ-D 归档流程。目标文件固定为当前工作目录下的 `./faq.md`。

请按以下规则处理：

1. 只在当前会话的当前活动分支中查找，优先从最近的消息向前寻找 `<!-- pi-faq-a:begin -->`。选择最近一次 FAQ-A 请求，不要选择更早的一次，也不要把其他会话或无关话题混入。
2. 以该 FAQ-A 请求为起点，收集同一问题相关的可见对话，直到 `/faq-d` 之前最近的相关助手结果为止。包括 PDF 页码、原问题、用户的补充问题、用户的尝试或纠正，以及助手的相关回答。若中间出现明显无关话题，只保留 FAQ-A 相关消息。
3. `<!-- pi-faq-a:final -->` 可作为 FAQ-A 最终答复的边界提示；如果后续用户围绕同一问题继续交互，应把后续相关交互和最新结论一起归档。只记录会话中实际可见的用户/助手内容；不要暴露或写入模型的隐藏思考。工具调用和工具输出只在有助于理解答案时做简洁摘要。
4. 如果当前上下文因 compaction 不完整，可使用环境变量 `PI_SESSION_FILE` 指向的 JSONL session 文件作为补充来源。按 JSONL 的 `message` 顺序读取并尽量只保留当前活动分支；不要把其他分支的内容当成当前交互。若无法恢复完整记录，归档已确认的部分，并在文件中注明缺失范围。
5. 若找不到任何 FAQ-A 标记，也找不到最近可见的 `/faq-a` 相关请求，不要创建或修改 `faq.md`，直接说明没有可归档内容。
6. 先检查 `./faq.md` 是否存在。不存在时创建；存在时必须保留全部已有内容并在末尾追加，不得覆盖或删除旧记录。写入前读取现有文件，并用安全的追加或读改写方式完成操作；写入后核对新记录确实位于文件末尾。
7. 如果 `faq.md` 中已经有完全相同的 PDF 页码、原问题和最终结果，则不要重复追加，只报告该记录已经存在。若本轮有新的相关交互或更新后的最终结果，应追加新记录。

新记录使用下面的 Markdown 结构。标题请根据问题生成简短、准确的中文标题；保留原问题和最终结果的实质内容，不要杜撰信息：

```markdown
<!-- pi-faq-record: source=faq-a -->
## <问题标题>

- PDF 页码：<页码>

### 问题
<原问题>

### 交互记录
<按时间顺序记录相关的用户消息，以及必要的助手/工具操作摘要>

### 最终结果
<最近一次相关的最终助手答复>
```

完成后向用户报告：使用了哪一页、归档到哪个路径，以及是创建还是追加；不要把无关会话内容打印出来。
